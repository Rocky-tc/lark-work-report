# 能力适配契约

## 目标

核心流程只依赖本文件定义的操作语义，不依赖 Codex、Claude、ChatGPT 或其他宿主的专有工具名。适配器可以是宿主原生连接器、MCP 工具、其他 Skill、`lark-cli`，也可以是用户提供的导出文件。

## 选择顺序

按以下顺序选择能完成任务且已获用户授权的实现：

1. 宿主已经连接的飞书原生工具或 MCP；
2. 当前环境中已安装并认证的 `lark-cli`；
3. 用户提供的 Markdown、JSON、CSV、文档或消息导出材料。

不要为了使用某个适配器切换全局身份、修改全局配置、扩大权限或要求用户重复提供已经可用的数据。不同数据域可以混用适配器，但必须在覆盖说明中记录实际来源。

## 统一操作

### `identity.current`

返回当前主体的稳定标识、可展示名称和时区。无法获取稳定标识时，使用“当前用户”，但不得把其他成员的活动归到当前用户。

### `candidate.list`

按数据域和左闭右开时间窗列出候选元数据，至少保留：

- `id`：当前适配器内稳定且可用于正文读取；
- `domain`：`calendar`、`im`、`docs`、`wiki`、`base`、`tasks`、`minutes`、`vc` 或 `report_cache`；
- `occurred_at`；
- `source_url` 或其他可核验来源标识；
- 用于工作相关性判断的最少必要元数据；
- `cursor` 或等价分页状态。

适配器可以返回更多字段，但在分类完成后必须丢弃确定属于私人或闲聊候选的详情。

### `candidate.fetch`

根据候选 `id` 读取足够正文和上下文，用于确认工作归属、状态、产出、结果、决策、风险和下一步。只允许对抓取队列中的 `work` 与 `uncertain` 调用。

返回正文时必须同时返回可核验来源标识。若适配器无法提供稳定链接，使用“来源类型 + 稳定 ID + 时间”作为来源锚，并在覆盖说明中披露限制。

### `report.create`

用标题和 Markdown 正文创建新的飞书文档，返回文档稳定标识和 URL。此操作是可选能力；不得把创建其他文档格式冒充为飞书文档。

### `report.fetch`

按 `report.create` 返回的稳定标识回读新文档，返回标题和正文。只有同时支持创建与回读时，才把飞书文档设为默认交付。

## `lark-cli` 适配器

使用已经配置并认证的 profile，不修改全局 profile。个人资源使用个人身份：

```bash
lark-cli --profile <lark-profile> --as user <domain> <command>
```

具体子命令以本机 `lark-cli --help` 和相应域的当前文档为准。不要把示例命令、旧版命令或其他环境的 profile 直接照搬。

## 宿主工具或 MCP 适配器

先检查工具说明和参数 schema，再把工具映射到统一操作。宿主把“搜索”和“读取”合并为一次调用时，仍需先用可用元数据做过滤；不得因为接口合并就读取已能确定为私人或闲聊的对象。

宿主工具不支持某个数据域时，记录为权限或能力缺口，继续其他数据域。不要反复重试同一个确定不支持的操作。

## 导出材料适配器

用户提供的文件只覆盖文件中实际包含的数据域和时间窗。把每个文件或记录的原始位置作为来源锚。无法确认主体、时间或来源时标为 `uncertain`，不得宣称覆盖了完整飞书。

离线模式默认交付 Markdown 草稿；除非另有可用输出适配器，否则不创建飞书文档。

## 调用计数

- 每次外部工具、MCP 或 `lark-cli` 请求计为 1 次调用。
- 本地脚本执行和对已返回结果的本地分析不计外部调用。
- 一个宿主工具在单次请求中返回多个域时仍计 1 次，但要分别记录覆盖域。
- 重试计入预算。

达到报告策略硬上限后停止扩散，使用已有证据完成报告并披露缺口。
