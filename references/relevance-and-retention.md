# 工作相关性与证据保留

## 判断目标

“可访问”不等于“应该抓正文”。先收集低成本元数据并预分类；确定为私人或闲聊的候选不抓正文。只有工作和待复核候选进入正文抓取队列。

## 四类标签

| 标签 | 定义 | 正文抓取与报告用途 |
|---|---|---|
| `work` | 元数据已经指向明确工作流 | 抓正文；确认后进入工作章节 |
| `uncertain` | 可能相关，但仅凭元数据无法确认 | 抓必要正文；进入独立待复核区或转为工作 |
| `private` | 元数据明确为家庭、健康、医疗、个人财务、证件等私人事项 | 不抓正文、不进文档 |
| `chatter` | 元数据和可见摘要明确为无工作行动或结果的闲聊 | 不抓正文、不进文档 |

## 分类步骤

先基于元数据回答：

1. 是否被明确标为私人，或属于明确的私人事项？
2. 是否明确只是闲聊，且没有工作行动、产出、决策、风险或工作流关系？
3. 是否已有足够信号归入明确工作流？

问题 1 或 2 为“是”时分别标 `private` 或 `chatter` 并停止。问题 3 为“是”标 `work`；其余全部标 `uncertain`。不要为了减少抓取而把模糊候选推断成私人或闲聊。

## 特殊来源

- 一对一聊天可能是真实工作沟通，不能仅凭位置跳过。
- 个人空间文档可能是工作草稿，不能仅凭位置跳过。
- 同事身份、工作时间、工作关键词都只是弱信号。
- 工作内容即使敏感，也只概括必要事实并附原始来源锚；不要复制不必要的个人信息。
- 确定的私人或闲聊候选即使命中项目关键词，也不能进入正文抓取队列。

## 用户范围控制

支持：

- `include_chats` / `exclude_chats`
- `include_folders` / `exclude_folders`
- `include_workstreams`
- `exclude_keywords`

这些参数限定本次候选范围，不改变原始对象权限。

## 模糊项

- `uncertain` 进入报告的独立“待复核”章节，不进入工作证据账本。
- 每条待复核项只包含必要描述、来源锚和待复核原因，不复制长段原文。
- 高业务价值候选最多向用户请求一次确认；确认后才可转入工作章节。
- 报告只显示 `work` 与 `uncertain` 的内容和数量，不显示 `private`、`chatter` 的计数或详情。

## 保留模式

### `ephemeral`（默认）

- 工作、待复核候选及其上下文只存在于本次运行的隔离临时目录或内存。
- 使用 `prepare-run.py` 返回的受管临时目录，不另行创建或选择系统外路径冒充临时运行。
- 新报告创建并 fetch 回读成功后，清理临时证据。
- 最终只保留报告、来源锚和聚合覆盖统计。
- 临时证据不得上传、共享、发布或进入日报→周报→月报缓存。

### `persistent`（仅显式选择）

- 只有用户明确说要“持久化证据”“保留候选/上下文以供复核”或等价意图时启用。要求“本地报告缓存”不是持久化证据授权。
- 在执行前向用户展示证据包位置；使用用户指定位置，或一个明确的个人隔离目录。
- 保存工作与待复核来源引用、读取上下文、分类、分类理由和实际采用的工作证据。
- `persistent_scope=work_only`：只保存 `work`。
- `persistent_scope=work_and_uncertain`：保存 `work` 和 `uncertain`，是持久化模式默认范围。
- `private` 与 `chatter` 永远不持久化。
- 不自动上传飞书、发布妙搭、共享给他人或作为团队缓存。

无论采用哪种保留模式，工作章节只读取 `work`；“待复核”章节只读取 `uncertain`。

## 清理验收

`ephemeral` 运行结束前确认：

1. 新报告已回读成功，或文档创建失败但对话草稿已交付；
2. 临时工作、待复核上下文和两个账本已删除；
3. 报告缓存中只有工作正文、待复核区和对应来源锚；
4. 报告中没有私人或闲聊计数、标题、参与人、摘要、原文或链接。

使用 `python3 scripts/manage-run.py cleanup --run-dir <run-dir>` 执行清理。脚本只删除系统临时根目录下、名称和运行标记都匹配的直接子目录；不得绕过校验删除其他路径。
