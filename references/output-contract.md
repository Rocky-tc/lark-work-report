# 输出与验收契约

## 默认交付

- 输出适配器支持创建并回读时，新建一篇飞书个人工作报告文档；否则交付 Markdown 草稿。
- 标题包含主体、周期和快照日期。
- 日报、周报、月报都使用统一六段式语义结构；存在有效个人模板时可替换显示名称和文本布局。
- 每个关键事实、结果、数字、完成状态和决策带 `[工作来源]` 锚。
- 独立“待复核”章节只包含待复核候选、原因和 `[待复核来源]` 锚。
- 页尾披露时间窗、快照时间、覆盖域、权限缺口和 work/uncertain 两类数量。

用户明确要求“只给草稿”时，仅输出 Markdown，并从调用预算中扣除创建与回读的 2 次。因能力缺失降级为草稿时，明确说明未创建飞书文档。

## 内容验收

- 信息顺序、字段和空章节由 [report-rendering.md](report-rendering.md) 与定稿器控制。个人模板只能改变显示层，不能删除或重排六个语义槽。
- 结果和影响必须有直接证据；来源冲突写成未决问题。
- `uncertain` 只进入待复核，不能支撑工作结论。
- 私人、闲聊及其分类计数不得进入文档。

## 覆盖说明

至少包含：

```markdown
- 时间窗：2026-07-20T00:00:00+08:00 至 2026-07-26T18:00:00+08:00
- 快照时间：2026-07-26T18:00:00+08:00
- 覆盖域：日历、消息、文档、任务、会议
- 权限缺口：话题群接口未覆盖
- 分类计数：work=12，uncertain=2
```

文档只能出现工作和待复核内容。不要出现私人或闲聊的标签、计数、标题、参与人、摘要、原文或链接。

来源锚优先使用可点击的 `https://` 地址。适配器无法提供链接时，使用 `source://<adapter_id>/<source_type>/<stable_id>`；这类稳定来源可以通过校验，但必须在覆盖说明中披露不可点击。

## 校验

先按 [report-rendering.md](report-rendering.md) 建立结构化报告模型，再运行合并式定稿器：

```bash
python3 scripts/finalize-run.py --run-dir <run-dir>
```

定稿器会在内存中调用渲染与校验逻辑，验证通过后才原子写入 `<run-dir>/report.md`。需要定位模型错误时，可分别调用 `render-report.py` 和 `validate-report.py`。

报告模型的 `profile` 必须与 `run-plan.json` 中周期解析得到的 `routed_profile` 一致，`ledger.json` 必须存在。所有 `errors` 必须修复。验证器按当前模板解析六个章节的显示名称，检查其唯一性与顺序、工作来源锚是否属于 `work` 账本、待复核原因与来源是否属于 `uncertain` 账本、带时区时间窗、快照、覆盖域、权限缺口、账本计数、占位符，以及私人/闲聊内容泄露。语义冲突、重复事项和事实准确性仍需对证据账本核验。

## 飞书文档创建与回读

1. 完整阅读 [capability-adapters.md](capability-adapters.md)。
2. 只有输出适配器同时提供 `report.create` 和 `report.fetch` 时才进入本流程。
3. 使用当前主体的个人身份创建新文档；若选用 `lark-cli` 适配器，命令形式为：

   ```bash
   lark-cli --profile <lark-profile> --as user docs +create <docs-create-arguments>
   ```

4. 从响应取得文档稳定标识和 URL。
5. 使用同一输出适配器与身份回读新文档。
6. 回读确认标题、所有必需章节、来源锚和覆盖说明存在。
7. 回读成功后才执行临时证据清理并宣告完成。

没有同时具备创建和回读能力时，跳过本流程，交付经过同一验证器检查的 Markdown 草稿。

## 默认边界

不生成实体关系图、检索路径、交接背景包、妙搭页面，不发送消息，不提交周报，不扩大访问范围。用户明确要求妙搭时，以已验证的报告文档为唯一事实源；这通常额外增加 3–6 次调用。
