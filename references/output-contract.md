# 输出与验收契约

## 默认交付

- 新建一篇飞书个人工作报告文档。
- 标题包含主体、周期和快照日期。
- 章节与报告策略一致。
- 每个关键事实、结果、数字、完成状态和决策带 `[工作来源]` 锚。
- 独立“待复核”章节只包含待复核候选、原因和 `[待复核来源]` 锚。
- 页尾披露时间窗、快照时间、覆盖域、权限缺口和 work/uncertain 两类数量。

用户明确要求“只给草稿”时，允许仅在对话输出 Markdown，并从调用预算中扣除创建与回读的 2 次。

## 写作规则

- 先写结论，再写证据支持的事实。
- 把相同工作流的多条活动合并为进展、产出、结果、风险和下一步。
- 结果和影响必须有直接证据；没有就省略，不用空泛措辞补齐。
- 清楚区分已完成、进行中、阻塞、待确认和计划。
- 来源冲突写成未决问题。
- `uncertain` 只能进入“待复核”章节，不能支撑工作结论。
- `private`、`chatter` 的计数和详情都不得进入文档。

待复核项统一写成：

```markdown
- 新方案探索可能属于本周工作；原因：工作流归属尚不明确。[待复核来源](https://...)
```

## 覆盖说明

至少包含：

```markdown
- 时间窗：2026-07-20T00:00:00+08:00 至 2026-07-27T00:00:00+08:00
- 快照时间：2026-07-26T18:00:00+08:00
- 覆盖域：日历、消息、文档、任务、会议
- 权限缺口：话题群接口未覆盖
- 分类计数：work=12，uncertain=2
```

文档只能出现工作和待复核内容。不要出现私人或闲聊的标签、计数、标题、参与人、摘要、原文或链接。

## 校验

先把草稿保存为 Markdown，再运行：

```bash
python3 <skill-dir>/scripts/validate-report.py --profile weekly --file <path-to-report.md>
```

所有 `errors` 必须修复。验证器检查章节、工作来源锚、待复核原因与来源、时间窗、快照、覆盖域、权限缺口、两类计数、占位符，以及私人/闲聊内容泄露。语义冲突、重复项和事实准确性仍需对证据账本人工核验。

## 飞书文档创建与回读

1. 完整阅读 `lark-doc` Skill 及其创建格式说明。
2. 使用个人身份创建：

   ```bash
   lark-cli --profile <lark-profile> --as user docs +create <按 lark-doc Skill 填写参数>
   ```

3. 从响应取得文档 token 和 URL。
4. 使用同一 profile 与身份 fetch 新文档。
5. 回读确认标题、所有必需章节、来源锚和覆盖说明存在。
6. 回读成功后才执行临时证据清理并宣告完成。

## 默认边界

不生成实体关系图、检索路径、交接背景包、妙搭页面，不发送消息，不提交周报，不扩大访问范围。用户明确要求妙搭时，以已验证的报告文档为唯一事实源；这通常额外增加 3–6 次调用。
