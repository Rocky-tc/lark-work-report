# 输出与验收契约

## 默认交付

- 输出适配器支持创建并回读时，新建一篇飞书个人工作报告文档；否则交付 Markdown 草稿。
- 标题包含主体、周期和快照日期。
- 日报、周报、月报都使用统一五段式正文结构；存在有效个人模板时可替换显示名称和文本布局。
- 每个关键事实、结果、数字、完成状态和决策带来源锚；单次来源使用 `[工作来源](...)`，重复来源可使用能解析到完整 URL 的 `W1` / `U1` 短引用。跨源聚合事项保留全部来源。
- 独立“待复核”章节只包含待复核候选、原因和 `[待复核来源]` 锚。
- 时间窗、快照时间、覆盖域、权限缺口和 work/uncertain 两类数量始终保留在内部模型与验收中。只有存在访问缺口或没有可用数据源时，页尾才显示无标题覆盖说明。

用户明确要求“只给草稿”时，仅输出 Markdown，并从调用预算中扣除创建与回读的 2 次。因能力缺失降级为草稿时，明确说明未创建飞书文档。

## 内容验收

- 信息顺序、字段和空章节由 [report-rendering.md](report-rendering.md) 与定稿器控制。个人模板只能改变显示层，不能删除或重排五个正文语义槽。标准阶段接口新建模型 v5，提交叙事字段、账本指纹和短引用；只有接口明确标记的简单单证据项可省略叙事。接口回填主体、周期、覆盖信息、真实证据 ID、行动事实和来源，并强制证明完整账本均已进入报告模型。
- 结果和影响必须有直接证据；来源冲突写成未决问题。
- `uncertain` 只进入待复核，不能支撑工作结论。
- 私人、闲聊及其分类计数不得进入文档。

## 覆盖说明

覆盖数据必须在内部完整包含时间窗、快照、覆盖域、权限缺口和双账本计数。默认不写入正文；存在访问缺口时显示：

```markdown
> 覆盖说明：已覆盖日历、消息、文档、任务、会议；未能访问话题群接口。
```

覆盖完整时不显示；没有可用数据源时显示 `> 覆盖说明：未发现可用数据源。`。不得输出独立“来源与覆盖”章节，也不向读者显示内部计数。

文档只能出现工作和待复核内容。不要出现私人或闲聊的标签、计数、标题、参与人、摘要、原文或链接。

来源锚优先使用可点击的 `https://` 地址。适配器无法提供链接时，使用 `source://<adapter_id>/<source_type>/<stable_id>`；这类稳定来源可以通过校验，但必须在访问缺口中披露不可点击。重复来源采用标准 Markdown 引用定义，例如正文 `[W1][W1]`，文末 `[W1]: https://example.com/source`；短引用不能跨账本或缺少定义。

## 校验

先按 [report-rendering.md](report-rendering.md) 建立结构化报告模型，再运行合并式定稿器：

```bash
python3 scripts/finalize-run.py --run-dir <run-dir>
```

定稿器会在内存中调用渲染与校验逻辑，验证通过后才原子写入 `<run-dir>/report.md`。需要定位模型错误时，可分别调用 `render-report.py` 和 `validate-report.py`。

v5 的 `profile`、标题和 `coverage` 不由 Agent 提交，而从 `run-plan.json`、`identity.json`、`extraction-audit.json` 与 `ledger.json` 回填；v1–v4 仍按旧契约校验。所有 `errors` 必须修复。验证器按当前模板解析五个正文章节的显示名称，检查其唯一性与顺序、全部工作来源锚是否属于 `work` 账本、待复核原因与来源是否属于 `uncertain` 账本、内部时间窗、快照、覆盖域、权限缺口、账本计数、条件覆盖说明、模型对全部聚合项的覆盖、占位符，以及私人/闲聊内容泄露。

## 飞书文档创建与回读

1. 完整阅读 [capability-adapters.md](capability-adapters.md)。
2. 只有输出适配器同时提供 `report.create` 和 `report.fetch` 时才进入本流程。
3. 使用当前主体的个人身份创建新文档；若选用 `lark-cli` 适配器，命令形式为：

   ```bash
   lark-cli --profile <lark-profile> --as user docs +create <docs-create-arguments>
   ```

4. 从响应取得文档稳定标识和 URL。
5. 使用同一输出适配器与身份回读新文档。
6. 回读确认标题、所有必需章节和来源锚存在；内部覆盖数据有访问缺口时，额外确认无标题覆盖说明存在且完整。
7. 回读成功后才执行临时证据清理并宣告完成。

没有同时具备创建和回读能力时，跳过本流程，交付经过同一验证器检查的 Markdown 草稿。

## 默认边界

不生成实体关系图、检索路径、交接背景包、妙搭页面，不发送消息，不提交周报，不扩大访问范围。用户明确要求妙搭时，以已验证的报告文档为唯一事实源；这通常额外增加 3–6 次调用。
