# 统一采集策略

## 采集对象

V1 只收集当前登录用户在确定时间窗内的个人工作活动。先解析：

- 主体：当前用户；
- 时间窗：北京时间、左闭右开；尚未结束的当前周期把采集终点截到实际快照时间；
- 工作范围：全部工作或用户指定的工作流、群、文件夹、关键词；
- 报告策略与深度；
- 证据保留模式。

所有现有飞书对象保持只读。不要切换为其他成员身份，不扩大访问权限。

## 数据域与顺序

所有报告共享以下接口类型，实际分页深度由策略决定：

1. 当前用户身份。
2. 已生成的日报、周报或月报缓存。
3. 日历与会议。
4. 当前用户发出的消息及其必要上下文。
5. 当前用户创建、编辑、评论、分享或被引用的文档、Wiki、Base。
6. 任务创建、完成、更新、延期、重开和阻塞。
7. 高相关会议纪要、妙记和行动项。

完整阅读 [capability-adapters.md](capability-adapters.md)，把宿主可用能力映射到统一操作。优先使用已连接的原生工具或 MCP；使用 `lark-cli` 适配器时，每条命令都带：

```bash
lark-cli --profile <lark-profile> --as user
```

## 两段式采集

### 1. 元数据扫描与预分类

优先取时间、来源类型、容器、参与人、标题、引用、分享和工作流标签。元数据同时负责排序、预算分配和正文抓取前的硬过滤。

优先级从高到低：

1. 任务、工作会议、OKR、已有报告引用；
2. 活跃工作流、客户、产品或交付物关联；
3. 与同事协作、评论、分享且上下文指向工作；
4. 仅由时间、标题或同事身份形成的弱信号。

满足以下任一明确条件时，可以预分类为 `private` 或 `chatter` 并跳过正文：

- 对象被飞书或用户显式标为私人，且没有工作任务、会议、协作或引用关系；
- 元数据明确属于家庭、医疗、个人财务、证件等私人事项；
- 消息元数据和可见摘要明确是寒暄、表情、祝福、饭局或兴趣闲聊，且没有行动、产出、决策、风险或工作流关系。

仅凭个人空间、私聊、工作时间、同事参与或关键词命中不能判为私人/闲聊。证据不足时标 `uncertain`，进入受控正文核验。

把元数据候选写成 JSON 后，必须运行：

```bash
python3 <skill-dir>/scripts/prepare-fetch-queue.py --file <path-to-candidates.json>
```

只允许读取脚本输出的 `fetch_queue`。脚本输出只包含 `work` 和 `uncertain`；`private`、`chatter` 只有内部跳过数量，不携带候选详情。

### 2. 正文核验

按优先级读取 `fetch_queue` 的足够上下文，用于确认工作归属、状态、产出、结果、决策、风险和下一步。正文核验后只保留：

- `work`：进入工作证据账本；
- `uncertain`：进入待复核账本。

正文若证明候选实际属于私人或闲聊，立即丢弃，不保留详情，不写入报告。

## 缓存复用

```text
日报 → 周报 → 月报
```

- 周报先读本周日报，再补原始来源。
- 月报先读当月周报，再回查关键结果、指标、冲突和高风险事项。
- 缓存缺失时回退到原始采集并使用无缓存预算。
- 下层报告是二手证据；关键结论仍需原始来源锚。
- 一次采集输出多种报告时复用同一工作证据账本，不重复查询。
- “报告缓存”只指已创建并回读验证的飞书报告文档。不要另建本地 `work-report-cache`、数据库或报告镜像。
- 用户要求本地报告缓存时，说明该缓存形态不受支持；不要把这句话转换成创建持久化证据包。

## 调用预算

预算包含创建飞书文档和回读验证的 2 次调用。

| 模式 | 常规预算 | 硬上限 | 默认深挖 |
|---|---:|---:|---:|
| 日报 | 10–15 | 18 | 1 个事项 |
| 周报 | 18–26 | 32 | 3 个工作流 |
| 月报（有周报缓存） | 12–20 | 25 | 5 个高价值结论 |
| 月报（无缓存） | 28–40 | 45 | 按价值排序 |
| `deep` | 35–50 | 50 | 调用前提示成本 |

`quick` 使用常规预算下界并优先缓存；`standard` 使用常规预算；`deep` 只在用户明确说“deep”“深度报告”或“完整来龙去脉”并获知成本时使用。“尽量找全”“都看看”仍属于 `standard`，不能据此自动把预算扩大到 50 次。

## 分页和止损

- 使用较大的安全 `page_size`，但不要把 `has_more=false` 当成唯一停止条件。
- 每次翻页前计算剩余预算与预期证据收益。
- 同一域连续两轮没有新增 `work` 或 `uncertain` 候选时停止。
- 日报不追溯项目前史；周报只深挖重点工作流；有缓存月报只复核关键结论。
- 只有状态冲突、重要决策、结果缺证、低置信度高优事项或用户要求完整来龙去脉时，才用文档 token、评论、消息现场和会议逐字稿定向反查。
- 达到硬上限立即停止，保留已确认工作证据并披露未覆盖范围。

## 权限与失败

| 情况 | 处理 |
|---|---|
| 单个对象无权限 | 记录缺口，继续其他来源 |
| 整个数据域缺 scope | 说明未覆盖，不反复重试 |
| 话题群或特定接口不覆盖 | 披露接口边界 |
| 限流或瞬时错误 | 有界重试，重试计入预算 |
| 缓存不存在 | 切换无缓存预算 |
| 文档创建或回读能力不可用 | 交付 Markdown 草稿，不修改其他对象 |
