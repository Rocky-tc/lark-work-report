# 统一采集策略

## 采集对象

V1 只收集当前登录用户在确定时间窗内的个人工作活动。先解析：

- 主体：当前用户；
- 时间窗：北京时间、左闭右开；尚未结束的当前周期把采集终点截到实际快照时间；
- 工作范围：全部工作或用户指定的工作流、群、文件夹、关键词；
- 报告策略与深度；
- 证据保留模式。

所有现有飞书对象保持只读。不要切换为其他成员身份，不扩大访问权限。

## 数据域与顺序

先确认当前用户身份，再按收益顺序查询：已有报告缓存，日历与会议，当前用户相关的消息、文档、Wiki、Base、任务、邮件、OKR、审批、会议纪要和行动项。实际覆盖域由适配器能力和用户范围决定。

优先使用已授权的宿主连接器或 MCP，其次使用已认证 CLI，最后使用用户导出材料。具体适配语义见 [capability-adapters.md](capability-adapters.md)。

## 两段式采集

### 1. 元数据扫描与预分类

优先取时间、来源类型、容器、参与人、标题、引用、分享和工作流标签，用于排序、预算分配和抓取前过滤。分类语义以 [relevance-and-retention.md](relevance-and-retention.md) 为准；本文件不重复定义。

把元数据候选写成 JSON 后，必须运行：

```bash
python3 scripts/prepare-fetch-queue.py \
  --file <run-dir>/candidates.json \
  --run-plan <run-dir>/run-plan.json \
  --output <run-dir>/fetch-queue.json
```

只允许读取脚本写入队列文件的 `fetch_queue` 和 `fetch_batches`。脚本拒绝已经混入的正文、无时区时间、重复稳定 ID 和非规范来源类型，再按字段白名单重建并跨域去重。队列文件和终端摘要都不保留 `private`、`chatter` 的详情或分类计数。

### 2. 正文核验

按优先级读取 `fetch_queue` 的足够上下文，用于确认工作归属、状态、产出、结果、决策、风险和下一步。正文核验后只保留：

- `work`：进入工作证据账本；
- `uncertain`：进入待复核账本。

正文若证明候选实际属于私人或闲聊，立即丢弃，不保留详情，不写入报告。

## 缓存复用

```text
日报 → 周报 → 月报
```

- 周报先读本周日报，再补原始来源。
- 月报先读当月周报，再回查关键结果、指标、冲突和高风险事项。
- 缓存缺失时回退到原始采集并使用无缓存预算。
- 下层报告是二手证据；关键结论仍需原始来源锚。
- 一次采集输出多种报告时复用同一工作证据账本，不重复查询。
- “报告缓存”只指已创建并回读验证的飞书报告文档。不要另建本地 `work-report-cache`、数据库或报告镜像。
- 用户要求本地报告缓存时，说明该缓存形态不受支持；不要把这句话转换成创建持久化证据包。

## 调用预算

预算包含创建飞书文档和回读验证的 2 次调用。

| 模式 | 常规预算 | 硬上限 | 默认深挖 |
|---|---:|---:|---:|
| 日报 | 10–15 | 18 | 1 个事项 |
| 周报 | 18–26 | 32 | 3 个工作流 |
| 月报（有周报缓存） | 12–20 | 25 | 5 个高价值结论 |
| 月报（无缓存） | 28–40 | 45 | 按价值排序 |
| `deep` | 35–50 | 50 | 调用前提示成本 |

`quick` 使用常规预算下界并优先缓存；`standard` 使用常规预算；`deep` 只在用户明确说“deep”“深度报告”或“完整来龙去脉”并获知成本时使用。“尽量找全”“都看看”仍属于 `standard`，不能据此自动把预算扩大到 50 次。

默认运行由 `prepare-run.py` 自动选择 `daily`、`weekly`、`monthly_cached`、`monthly_uncached` 或 `deep`。单次外部调用前执行 `record-call`；同一批或并行波次用 `record-batch` 一次原子预留。它是硬上限执行器，不替代常规预算和收益止损。

## 分页和止损

- 使用较大的安全 `page_size`，但不要把 `has_more=false` 当成唯一停止条件。
- 每次翻页前计算剩余预算与预期证据收益。
- 同一域连续两轮没有新增 `work` 或 `uncertain` 候选时停止。
- 日报不追溯项目前史；周报只深挖重点工作流；有缓存月报只复核关键结论。
- 只有状态冲突、重要决策、结果缺证、低置信度高优事项或用户要求完整来龙去脉时，才用文档 token、评论、消息现场和会议逐字稿定向反查。
- 达到硬上限立即停止，保留已确认工作证据并披露未覆盖范围。

## 权限与失败

| 情况 | 处理 |
|---|---|
| 单个对象无权限 | 记录缺口，继续其他来源 |
| 整个数据域缺 scope | 说明未覆盖，不反复重试 |
| 话题群或特定接口不覆盖 | 披露接口边界 |
| 限流或瞬时错误 | 有界重试，重试计入预算 |
| 缓存不存在 | 切换无缓存预算 |
| 文档创建或回读能力不可用 | 交付 Markdown 草稿，不修改其他对象 |
